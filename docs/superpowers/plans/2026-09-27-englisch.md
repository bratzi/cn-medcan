# Englisch-Umschalter Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Die Oberfläche (ohne `/admin`) lässt sich per Cookie auf britisches Englisch umschalten, URLs bleiben gleich, Deutsch ist Standard.

**Architecture:** Zwei eigene Wörterbücher (`lib/i18n/de.ts` als Quelle, `lib/i18n/en.ts` typgleich), eine reine Nachschlage- und Platzhalterfunktion, Sprache aus Cookie `sprache` (sonst Accept-Language, sonst `de`), gelesen einmal je Anfrage über React `cache`. Server Components lesen das Wörterbuch direkt, Client Components bekommen nur ihren Ausschnitt als Props. Umschalter und Accept-Language-Erkennung bleiben hinter einem Schalter aus, bis alle fünf Wellen übersetzt sind.

**Tech Stack:** Next.js 16.3 App Router auf Cloudflare Workers (OpenNext), React 19, TypeScript, Tests mit `node:test` über `tsx --test` (nicht Vitest), Prisma + D1.

**Spec:** `docs/superpowers/specs/2026-09-26-englisch-umschalter-design.md` (freigegeben 2026-09-27: Accept-Language ja, `en-GB`, Umschalter erst sichtbar, wenn alle Wellen übersetzt sind).

## Global Constraints

- Sprache nur über Cookie `sprache` (`de` | `en`); **keine** URL-Änderung, **keine** Änderung an `proxy.ts`.
- Übersetzt wird nur die Oberfläche; Nutzer- und Betreiberinhalte, Eigennamen, die Wortmarke „Book of Terpz“ und URLs bleiben unverändert.
- `/admin` bleibt komplett deutsch (inkl. `components/admin/**`, `app/admin/**`).
- Englisch = `en-GB`, britische Schreibweise (flavour, colour, favourite), Ton sachlich, Du-Form → neutrales „you“.
- **HWG:** kein englischer Text darf werblicher klingen als der deutsche; keine Wirkungsversprechen, keine Preis-Lockrufe.
- Keine neue npm-Abhängigkeit (kein `next-intl`, kein `negotiator`).
- Das Wörterbuch darf nicht ins Browser-Paket: kein `"use client"`-Modul importiert `lib/i18n/de`, `lib/i18n/en` oder `lib/i18n/index` als Wert (Typimporte erlaubt).
- `Intl`-Objekte nur als Modulkonstanten bzw. einmal je Isolat gebaut (CPU-Rahmen, `.claude/skills/edge-stack-master.md` §1).
- Kein lokales `next dev`/`build`/`preview`: `npm run typecheck && npm test`, commit, push, live per Browser-MCP prüfen. Nach einem Code-Push ~13 min kein weiterer Code-Push (bricht den Cloudflare-Build ab); HANDOFF-Pushes sind ausgenommen.
- Commits deutsch, Conventional Commits, mit Zeile `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. CRLF-Dateien bleiben CRLF.
- Schalter `I18N_OEFFENTLICH` in `lib/i18n/schalter.ts` steht bis Task 11 auf `false`.

## Abweichungen von der Spec (Entscheidung Claude beim Planen, bitte beim Review bestätigen)

1. **Meldungen (Spec 5.3):** Prüffunktionen (`lib/*-eingabe.ts`) geben Meldungs**schlüssel** zurück (testbar, sprachfrei), aber die **Server Action löst den Schlüssel selbst** in der Sprache der Anfrage auf und gibt wie heute einen Text zurück. So bleibt jede Client-Komponente unverändert und bekommt kein Meldungswörterbuch. Der Sonderfall „Sprache wechselt zwischen Absenden und Anzeigen“ wird bewusst nicht behandelt.
2. **Accept-Language (Spec 4.1):** Gewinnt der erste Eintrag mit `de`/`en` nach Gewicht (bei Gleichstand die Reihenfolge). `fr, en;q=0.8` ergibt also `en`, nicht `de`: wer Englisch als Zweitsprache nennt, liest es eher als Deutsch.
3. **Feste Wörter in `lib/format.ts` (Spec 6):** „k. A.“, „Werktag(e)“, „Preis auf Anfrage“ stehen je Sprache **in `lib/format.ts`**, nicht im Wörterbuch, weil `format.ts` auch von Client Components importiert wird und sonst beide Wörterbücher ins Browser-Paket zöge.
4. **Benachrichtigungen (Spec 5.4):** Neue Spalte `parameter` (JSON-Text, optional); `text` bleibt Pflicht und wird weiter deutsch geschrieben (Rückfall für alte Leser und späteren Mailversand). So reicht ein `ALTER TABLE … ADD COLUMN` statt eines Tabellenumbaus, und die Trigger aus `db/constraints.sql` bleiben unberührt.
5. **Test-Einstieg ohne sichtbaren Schalter:** Solange `I18N_OEFFENTLICH = false`, setzt `GET /api/sprache?wahl=en` (bzw. `de`) das Cookie und leitet auf `/` um. Liegt hinter dem Gate-Passwort.
6. **Rechtstexte:** `/impressum`, `/datenschutz` und `lib/rechtliches.ts` bleiben deutsch (rechtlich maßgebliche Fassung); nur die Linktexte im Fuß werden übersetzt.
7. **`/zugang`** wird durch das sprachlesende Root-Layout wieder dynamisch; die Messung aus Caching v2 zeigte für die statische Fassung keinen Gewinn.

```ts
/**
 * Sprachwahl als reine Funktionen (Spec Englisch 4.1): ohne Request, ohne
 * Next, damit jede Regel fuer sich testbar ist. lib/i18n/sprache.ts liest
 * Cookie und Header und ruft nur bestimmeSprache().
 */
export const SPRACHEN = ["de", "en"] as const;
export type Sprache = (typeof SPRACHEN)[number];
export const SPRACH_COOKIE = "sprache";

export function istSprache(wert: unknown): wert is Sprache {
  return wert === "de" || wert === "en";
}

/**
 * Erster Eintrag mit de oder en nach Gewicht, bei Gleichstand die Reihenfolge.
 * Andere Sprachen zaehlen nicht mit; q=0 und kaputte Gewichte fallen raus.
 */
export function spracheAusAcceptLanguage(zeile: string | null): Sprache | null {
  if (!zeile) return null;
  const kandidaten = zeile
    .split(",")
    .map((teil, index) => {
      const [tag = "", ...optionen] = teil.trim().toLowerCase().split(";");
      const q = optionen.map((o) => o.trim()).find((o) => o.startsWith("q="));
      const gewicht = q === undefined ? 1 : Number(q.slice(2));
      return { basis: tag.trim().split("-")[0], gewicht: Number.isFinite(gewicht) ? gewicht : 0, index };
    })
    .filter((k) => k.gewicht > 0 && istSprache(k.basis))
    .sort((a, b) => b.gewicht - a.gewicht || a.index - b.index);
  const erster = kandidaten[0]?.basis;
  return istSprache(erster) ? erster : null;
}

export function bestimmeSprache(eingabe: {
  cookie: string | undefined;
  acceptLanguage: string | null;
  erkennungAktiv: boolean;
}): Sprache {
  if (istSprache(eingabe.cookie)) return eingabe.cookie;
  if (eingabe.erkennungAktiv) return spracheAusAcceptLanguage(eingabe.acceptLanguage) ?? "de";
  return "de";
}
```

import type { Sprache } from "./sprache-kern";
import type { Mehrzahl, Meldung, Woerterbuch } from "./typen";

type Parameter = Record<string, string | number>;

/** {name} durch parameter.name ersetzen; Unbekanntes bleibt sichtbar stehen. */
export function t(text: string, parameter: Parameter = {}): string {
  return text.replace(/\{(\w+)\}/g, (ganz, name: string) => (name in parameter ? String(parameter[name]) : ganz));
}

const REGELN: Record<Sprache, Intl.PluralRules> = {
  de: new Intl.PluralRules("de-DE"),
  en: new Intl.PluralRules("en-GB"),
};

export function mehrzahl(sprache: Sprache, eintrag: Mehrzahl, anzahl: number, parameter: Parameter = {}): string {
  const form = REGELN[sprache].select(anzahl) === "one" ? eintrag.one : eintrag.other;
  return t(form, { anzahl, ...parameter });
}

export function meldungText(w: Woerterbuch, meldung: Meldung): string {
  return t(w.meldung[meldung.schluessel], meldung.parameter);
}

const DEUTSCH =
  /[äöüÄÖÜß]|\b(und|oder|nicht|mit|für|bitte|Bitte|keine?|noch|eine?|wird|werden|ist|sind|zur|zum|dein|deine|wir|uns|Sie|jetzt|hier|alle|wählen)\b/;

function ohneKommentare(quelle: string): string {
  return quelle
    .replace(/\/\*[\s\S]*?\*\//g, "")
    .replace(/\{\s*\/\*[\s\S]*?\*\/\s*\}/g, "")
    .replace(/(^|[\s;])\/\/.*$/gm, "$1");

function texte(quelle: string): string[] {

  for (const m of quelle.matchAll(/>([^<>{}]+)</g)) aus.push(m[1]);
  return aus.map((s) => s.trim()).filter(Boolean);
}

```ts
import type { Woerterbuch } from "@/lib/i18n/typen";
import { t } from "@/lib/i18n/text";

export type BenachrichtigungParameter = { handelsname: string; begruendung?: string | null };

export function vorlageFreigegeben(handelsname: string) {
  return {
    art: "VORSCHLAG_FREIGEGEBEN" as const,
    text: textFreigegeben(handelsname),
    parameter: JSON.stringify({ handelsname } satisfies BenachrichtigungParameter),
  };
}

export function vorlageAbgelehnt(handelsname: string, begruendung: string | null) {
  return {
    art: "VORSCHLAG_ABGELEHNT" as const,
    text: textAbgelehnt(handelsname, begruendung),
    parameter: JSON.stringify({ handelsname, begruendung } satisfies BenachrichtigungParameter),
  };
}

function parameterLesen(roh: string | null): BenachrichtigungParameter | null {
  if (!roh) return null;
  try {
    const wert: unknown = JSON.parse(roh);
    if (wert && typeof wert === "object" && typeof (wert as { handelsname?: unknown }).handelsname === "string") {
      return wert as BenachrichtigungParameter;
    }
  } catch {}
  return null;
}

/** Satz in der Sprache des Lesers; alte oder unlesbare Zeilen zeigen ihren gespeicherten Text. */
export function benachrichtigungSatz(
  w: Woerterbuch["benachrichtigung"],
  zeile: { art: string; text: string; parameter: string | null },
): string {
  const p = parameterLesen(zeile.parameter);
  if (!p) return zeile.text;
  if (zeile.art === "VORSCHLAG_FREIGEGEBEN") return t(w.freigegeben, { handelsname: p.handelsname });
  if (zeile.art === "VORSCHLAG_ABGELEHNT") {
    const satz = t(w.abgelehnt, { handelsname: p.handelsname });
    return p.begruendung ? t(w.abgelehntMitGrund, { satz, begruendung: p.begruendung }) : satz;
  }
  return zeile.text;
}
```
