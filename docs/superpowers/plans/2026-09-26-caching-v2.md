# Caching v2 gegen Fehler 1102 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans oder superpowers:subagent-driven-development.
> Schritte mit Checkbox (`- [ ]`). **Start erst nach Nutzerfreigabe von Spec und Plan** (Wellenplan Punkt 12).

**Goal:** Warme Aufrufe der Hauptseiten bleiben unter 10 ms CPU (kein 1102), ohne Paid, ohne neue Dienste in
den ersten Schritten.

**Architecture:** Erst Grundlast senken (isolatweite Clients, kein Better Auth für Anonyme, kein Schreiben je
Render, keine Doppelabfragen), dann geteilte Rohdaten pro Isolat mit TTL merken (`lib/memo.ts`), dann
statische Seiten wirklich statisch. Kein HTML-Cache (Sprach-Cookie, Rolle, Sitzung). Plattform-Caches nur als
optionaler letzter Schritt nach Messung und Entscheid.

**Spec:** `docs/superpowers/specs/2026-09-26-caching-v2-design.md`

## Global Constraints

- **Verboten:** `staticAssetsIncrementalCache` zusammen mit `enableCacheInterception`; `"remote": true` an
  einem Binding in `wrangler.jsonc`; `cacheComponents: true`; R2, KV-Incremental-Cache, DO-Queue, Paid.
- Kein lokales `next dev`/`build`/`preview` (Projektregel „Live statt Dev“): `npm run typecheck && npm test`,
  commit, push, Cloudflare baut, live messen. Keine Polling-Schleifen, keine Retries bei Netzfehler.
- **Ein Schritt = ein Commit.** Rücknahme immer `git revert <sha>` + push; kein Schritt ändert Bindings (außer
  optional Schritt 8 nach Freigabe).
- Nach **jedem** Schritt derselbe Messlauf wie Schritt 0 (nur die betroffenen URLs), Ergebnis als Zeile in die
  Messtabelle unten und in HANDOFF.md.
- Regeln: `.claude/skills/edge-stack-master.md` (Zugriff auf Bindings nur über `lib/cloudflare.ts`, Client nur
  über `getPrisma()`, Sichtbarkeit nur über `bestandSichtbarkeit()`).
- Commit-Nachrichten deutsch, Conventional Commits, mit `Co-Authored-By`-Zeile. CRLF-Dateien bleiben CRLF.

## Review Focus

1. Preise erscheinen nie ohne Fachkreis-Rolle — auch nicht aus einem gemerkten Eintrag (Schritt 6, Schlüssel mit `fk=`).
2. Angemeldete bleiben angemeldet, nachdem die Cookie-Abkürzung greift (Schritt 3).
3. Kein „Cannot perform I/O on behalf of a different request“ im tail nach Schritt 2 und 6.
4. Eigene Stimme sofort sichtbar; Zählstände dürfen bis TTL nachlaufen.
5. `/produkte/gibt-es-nicht` antwortet weiter 404, auch mit gemerktem Detail (Schritt 5/6).

### Schritt 6: Geteilte Daten pro Isolat merken

**Files:** Create `lib/memo.ts`, `tests/memo.test.ts`, `tests/memo-ohne-nutzerdaten.test.ts`;
Modify die Lader in `lib/query/strains.ts`, `lib/query/reviews.ts`, `lib/query/umfragen.ts`, Admin-Aktionen.
**Voraussetzung:** Nutzerentscheid TTL (60 s oder 300 s).
**Erwartete Ersparnis:** bei warmem Isolat entfallen auf der Startseite (anonym) alle ~9 Prisma-Abfragen samt

- [ ] **6.1 `lib/memo.ts`:**

```ts
/**
 * Geteilte, nutzerunabhaengige Daten pro Isolat merken (Spec Caching v2, Stufe B).
 * Nur aufgeloeste Werte, nie eine offene Promise ueber Request-Grenzen (workerd-I/O-Regel).
 * Nie Sitzung, Rolle als Wert oder Cookies hier hinein - Rolle nur als Teil des Schluessels.
 */
const MAX_EINTRAEGE = 64;
const speicher = new Map<string, { wert: unknown; bis: number }>();

export async function merke<T>(schluessel: string, ttlMs: number, lader: () => Promise<T>): Promise<T> {
  const jetzt = Date.now();
  const treffer = speicher.get(schluessel);
  if (treffer && treffer.bis > jetzt) return treffer.wert as T;
  const wert = await lader(); // Fehler werfen durch und werden nicht gemerkt
  speicher.delete(schluessel);
  speicher.set(schluessel, { wert, bis: jetzt + ttlMs });
  while (speicher.size > MAX_EINTRAEGE) speicher.delete(speicher.keys().next().value!);
  return wert;
}

export function vergiss(praefix: string): void {
  for (const schluessel of [...speicher.keys()]) if (schluessel.startsWith(praefix)) speicher.delete(schluessel);
}
```

  Hinweis: `Date.now()` steht in Workers während eines Requests still, zwischen Requests läuft es — für TTL genügt das.
